# 管理画面・条件付きアクション

管理画面は `/admin`、一般投票は `/` です。一般来場者の投票にはGoogleログインを要求しません。

## Google管理者ログイン

Google Cloud ConsoleでOAuth 2.0の**ウェブアプリケーション**クライアントを作成し、OAuth同意画面を設定します。承認済みリダイレクトURIには公開するドメインごとに次を登録してください。

- `https://YOUR-VERCEL-DOMAIN/api/admin/google/callback`
- `https://YOUR-CLOUDFLARE-DOMAIN/api/admin/google/callback`

各デプロイ先に次の環境変数を設定します。

- `GOOGLE_CLIENT_ID`：OAuthクライアントID
- `GOOGLE_CLIENT_SECRET`：OAuthクライアントシークレット（公開禁止）
- `GOOGLE_ADMIN_EMAILS`：許可するメールアドレスをカンマ区切りで列挙
- `VOTE_HMAC_SECRET`：32文字以上の秘密値

Googleの認可コード＋PKCEでログインし、Googleの署名済みIDトークンを検証します。メール認証済みかつ許可リストにあるアカウントだけが、8時間有効なHttpOnly Cookieで管理画面にアクセスできます。

## 管理機能

部門・候補の作成・編集、受付期間、公開状態、投票上限（1〜20）、公開ID、条件付きアクション（引換権・リンク・案内）、AND/OR条件、集計・使用済み処理を利用できます。編集内容は「まとめて保存」でTursoにトランザクション保存します。新規作成・並べ替え・引換処理は即時反映です。

## 引換権（来場者の端末でボタン1回）

来場者が条件を満たすと、投票ページに「引き換える」ボタンが表示されます。景品の受け渡し時に、委員会の前でこのボタンを押すと `action_claims` に記録され、画面が「引換済み」に変わります。**引換コードやスタッフ側の操作は不要です。** 管理画面の「集計」では件数を確認できます。

アクションごとに次を設定できます（`actions.config_json` に保存）。

- ボタンの文言と、押した後の表示（リンクの場合はボタンの文言）
- ボタンを押す前に確認を表示するかと、そのメッセージ（例：「このボタンは委員会が押してください。」）。新しい引換権では初期状態でオンです。

## 質問の選択肢を表で編集する

管理画面の部門編集では、候補名・ID・追加項目をスプレッドシート形式の表で編集できます。Googleスプレッドシートなどからコピーした範囲をそのまま貼り付けられ、表の末尾を超えた行は新しい候補として追加されます（名前が空の行は追加しません）。ドラッグ・Shift+クリックで範囲を選択してコピー・切り取りもできます。編集内容は右上の「保存」（Ctrl+S）でまとめて反映されます。

「表示する項目」では、名前と各追加項目について文字サイズ（12〜36px）・太字・斜体・下線・文字色を選べます。追加項目は項目名（「場所」などのラベル）を投票ページに表示しないこともできます。

## 公開ID（部門・候補）

- **部門の公開ID**（`polls.public_id`）はサイト全体で一意です。投票ページのURLに `?category=（公開ID）` を付けると、その部門を開きます。
- **候補ID**（`candidates.public_id`）は同じ部門の中で一意であればよく、**別の部門と同じIDを使えます**（例：同じ団体が複数部門にエントリー）。
- 複数の部門に同じ候補IDがあるとき、`/?id=候補ID` で開くと、どの部門に投票するかを選ぶダイアログが表示されます。
- `/?id=候補の公開ID&category=部門の公開ID` のように部門の公開IDを一緒に渡すと、ダイアログを出さずにその部門の候補へ移動します（管理画面の表の「開く」リンクはこの形式です）。

追加列は `polls.columns_json`（列キー・見出し・文字サイズ・文字スタイル・項目名の表示有無。名前の文字スタイルも `_name` として同じJSONに保存）、各候補の値は `candidates.extra_json`、候補名の表示サイズは `polls.name_font_size` に保存します。DBは新規作成専用の `db/schema.sql` に定義します。初期化後は `npm run check:db` で検証してください。

## セクションの追加と削除

管理画面での追加・並べ替え・削除は、右上の「保存」を押すまでサーバーに送られません。新しいセクションは選択中のセクションの直後に追加されます。

部門やアクションを削除すると、その候補・投票データ（引換権なら受け取り記録）も削除されます。投票ページに出したくないだけのときは「ページに表示」をオフにしてください。

## 複数のID

部門と候補の公開IDは、カンマ区切りで複数指定できます（例：`yakisoba,noodle`）。どのIDで開いても同じ部門・候補に移動します。重複のルール（部門の公開IDはサイト全体で一意、候補の公開IDは部門内で一意）は個々のIDごとに保存時にチェックされます。

## 運営情報

「設定」タブでイベントの運営団体名、公式サイトのURL、問い合わせ先メールアドレスを登録できます。運営団体名は投票ページのフッターとプライバシーポリシーに表示され、公式サイトURLを設定したときだけリンクが表示されます。未設定の項目は固定の祭り名などで補完しません。毎回の開催に合わせて情報を更新してください。

## デザイン（色とロゴ）

「設定」タブで、メインカラー・アクセントカラー・ハイライト・文字色・背景色と、左上のロゴ（タブのアイコンにも使用）を変更できます。値は `form_settings` テーブルに保存します。PNG・JPEG・WebPのロゴは128pxに縮小して保存し、SVGは140KBまでです。

## プレビュー

上部の目のアイコンで、保存前の内容（非公開の部門・アクションも含む）を投票ページの見た目で確認できます。PCとスマホの幅を切り替えられます。投票やボタンは動作しません。

## 集計のリセット

「集計」タブの「集計をリセット」で、すべての投票・引換権の受け取り記録・重複投票の防止データ（不審な投票の記録、送信回数の制限）を削除します。部門・候補・ページ構成・設定は残ります。確認のため「リセット」と入力する必要があり、元に戻せません。

## Tursoの読み書き行数を抑える工夫

- 投票ページの読み込みと条件付きアクションの判定は、投票者ごとのインデックス（`votes_voter`）で該当行だけを読みます（`npm run setup:db` で作成）。
- 投票後は部門・候補を読み直さず画面側で更新し、アクションがあるときだけその一覧を読み直します。
- 管理画面の保存では、変更のあった部門・アクション・項目と、位置が変わったブロックだけを書き込みます。
- 票数は`candidate_totals`に原子的に保持するため、集計画面で投票履歴を走査しません。正式票だけを加算し、条件判定専用の記録は集計に含みません。

## 説明文の書式

フォームの説明、部門・アクションの説明、見出しの説明、説明文ブロックでは、太字・斜体・下線・リンク・番号付きリスト・箇条書きと書式のクリアを使えます（入力中に欄の下へツールバーが出ます。リンクは Ctrl+K でも追加できます）。貼り付けた文章もこれらの書式だけに整えられます。保存時とページ表示時の両方で、許可した書式（b・i・u・a・ol・ul・li・div・br）以外は取り除かれ、リンクは https・http・mailto のみ有効です。

## ページ内リンク

説明文のリンクでは、リンク入力欄の「ページ内のセクション」から部門・見出し・説明文・アクションを選ぶと、そのセクションへのリンクになります（`#セクションのID`）。`#公開ID` と入力すると、その公開IDの部門や候補へ移動します。投票ページのURLの末尾に `#…` を付けて開いた場合も同じ位置へ移動します。

## フォント

「設定」タブの「デザイン → フォント」で、見出し（タイトル・部門名・見出し）と本文（説明文・候補名・ボタン）のフォントを選べます。システム標準以外は、投票ページを開いたときに Google Fonts から読み込みます（選んだフォントだけ）。
