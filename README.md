# イベント投票システム

イベントや学園祭などの一般公開投票を、来場者のログインや個別QRの配布なしで実施できるNext.jsアプリです。

- **Vercel**：Webサイト・投票API
- **Turso**：投票データ保存
- **Cloudflare Turnstile**：不正アクセス対策
- **署名付きHttpOnly Cookie**：同じブラウザからの再投票を防止
- **IPハッシュ＋ブラウザに依存しにくい端末情報のハッシュ**：同一組み合わせでの再投票を拒否（同型端末の誤判定には注意）
- **Cookieを超える送信回数制限**：IPとブラウザ情報の組み合わせで制御（IP単独では拒否しない）
- **管理画面で監視**：Google管理者ログイン後に疑わしい投票の件数を表示

初期状態は投票を受け付けません。Tursoにスキーマと投票部門を登録し、Vercelの環境変数を設定してください。

詳細： [セットアップ・運用手順](docs/voting.md)

> ブラウザのみでは物理的な1端末1票を厳密に保証できません。

## 管理画面

運営団体名・公式サイト・問い合わせ先、フォームタイトル、ロゴ、配色などを管理画面で設定できます。固有の祭り名や開催回はソースコードに埋め込まず、開催ごとに編集してください。公開投票は `/`、管理画面は `/admin` です。

新しいイベントで使う場合は空のTurso DBを用意し、`/admin` からタイトル・運営団体・問い合わせ先・ロゴを登録してください。既存DBのイベント情報は自動消去されません。Cloudflare Workersの`wrangler.jsonc`の`name`はデプロイ先固有のため、別のWorkerとして公開する場合だけ変更し、独自ドメインの割り当ても設定してください。


[管理画面・条件付きアクションの使い方](docs/admin-builder.md)

- /admin で部門・候補・1人あたりの選択候補上限・公開期間を管理できます。
- 追加機能は共通ルール（AND/OR、投票済み部門数、総票数、特定部門）で表示・実行条件を設定できます。
- 引換権・条件付きリンク・条件付き案内が利用できます。
- データベースは新規作成し、`db/schema.sql` から初期化してください。旧形式の移行は行いません。

### はじめてVercelへ公開する場合

GitHubからVercelへインポート後、TursoとTurnstileの環境変数を設定します。Turso CLIをインストールする必要はありません。

ローカルで`.env.local`に`TURSO_DATABASE_URL`と`TURSO_AUTH_TOKEN`を設定したうえで、`node --env-file=.env.local scripts/setup-db.mjs`を実行すると、必要なテーブルを安全に初期化・確認できます。詳細は[はじめての公開手順](docs/vercel-first-run.md)を参照してください。

### Tursoの初期化

空のTursoデータベースを用意し、`.env.local` に接続情報を設定して以下を実行します。

```sh
node --env-file=.env.local scripts/setup-db.mjs
node --env-file=.env.local scripts/setup-db.mjs --check
```

`db/schema.sql` が唯一のスキーマ定義です。既存データベースへの互換対応や移行処理はありません。
